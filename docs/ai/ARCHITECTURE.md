# Architektur – tatsächlicher Stand

`Protocol` (`netstandard2.0`) definiert binäre, versionierte Frames bis 64 KiB und typisierte Lobby-Payloads. `Network` (`netstandard2.0`) stellt eine TCP-Verbindung mit serialisiertem Senden, einem Reader und zeitbegrenztem Handshake bereit. `Lobby` (`netstandard2.0`) hält Sitzungen, Räume, Host-Rechte, Ready-Status und Revisionen unter einem Lock. `Hosting` (`netstandard2.1`) enthält den gemeinsamen autoritativen TCP-Listener, Handshake, Verteilung, Heartbeats mit ausstehenden Nonces und Bereinigung. `Server` (`net10.0`) ergänzt Konfigurationsdatei und SIGTERM/Strg+C-Shutdown für den eigenständigen Prozess. `ListenHost` startet denselben Hosting-Kern im RimWorld-Prozess ohne separates Serverprogramm. Alle Lobbyzustände sind flüchtig.

Datenfluss: `Client -> FrameCodec -> FoundationServer -> LobbyRegistry -> LobbyPayloads/FrameCodec -> betroffene Clients`. Der Server entscheidet über Mitgliedschaft und Rechte. Lobby-Snapshots besitzen monoton steigende Revisionen; der künftige Client soll ältere Revisionen verwerfen.

Der RimWorld-Adapter (`netstandard2.1`) nutzt `Verse.Mod` als Einstieg über Mod-Einstellungen und zeigt Verbindung/Lobby sowie den Direkt-Host-Knopf an. `LobbyClient` hält die Hintergrund-Leseschleife und Ping/Pong von Verse getrennt. Die UI verarbeitet nur Nachrichten aus einer threadsicheren Queue. Netzwerkbibliotheken referenzieren weder Verse noch Unity/Waylith. Lokales Ziel: RimWorld `1.6.4871`; `Version.txt` rev598, Runtime rev600, UI noch nicht nachgewiesen. Die erste Version simuliert keine Spielwelt. Authentifizierung und TLS fehlen; Standardbindung ist Loopback, LAN nur in kontrollierter Umgebung. Siehe `docs/protocol.md`, `docs/dedicated-server.md` und ADR 0002–0005.
