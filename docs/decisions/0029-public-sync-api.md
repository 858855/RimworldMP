# ADR 0029 – Öffentliche Sync-API v1 für andere Mods (API-001)

- **Status:** Vorschlag auf `feat/mod-api` (Sven, 2026-10-17), von `main` @ `060d2be`; Ziel RimWorld 1.6.4871, Unity/Mono. Letzte Nummer aus Svens ADR-Bereich 0024–0029. Setzt Plan §7.10 (lokale Roadmap C1–C3) um; API-002 (rwmt-Vertrag) und COMPAT-001 (Adapter, Matrix, Lobby-Warnung) bleiben offen.
- **Ziel:** Andere Mods machen ihre Spieleraktionen multiplayerfähig, ohne den Foundation-Code anzufassen: eine Methode als synchronisierten Befehl registrieren, eigene Typen serialisieren, eigenen Zustand in die Hash-Prüfung einbringen.
- **Bestand:** `GameCommandCodec` war eine if-Kette über drei private Opcodes (Draft, Forbid, Goto); ein unbekannter Opcode warf. Referenzen kannte nur `GameReferenceCodec.WriteThing` (platziertes Thing). `SessionStateHash` hatte keinen Erweiterungspunkt. Alle Typen des RimWorld-Projekts sind `internal`; `docs/extension-api.md` war ein Platzhalter.
- **Entscheidung:**
  - **Neues Assembly `Multiplayer.Foundation.Api`** (netstandard2.1, nur Verweis auf `Assembly-CSharp`, kein Harmony, keine Netzwerktypen; eigene SemVer `MP.ApiVersion = 1.0.0`). Inhalt: `MP` (`IsAvailable`, `IsInSession`, `IsHost`, `IsExecutingCommand`, `LocalPlayerKey`, `ExecutingIssuer`, `RegisterAll`, `RegisterSyncMethod`, `RegisterSyncWorker<T>`, `RegisterHashContributor`), Attribute `[SyncMethod]`, `[SyncWorker]`, `[SyncHash]`, abstrakter `SyncWorker` (`IsWriting`, `Write<T>`, `Read<T>`, `Bind<T>`), `MissingReferenceException`, `ISyncProvider` (nur für die Foundation). Der Foundation-Mod installiert im Konstruktor `FoundationSyncProvider`; andere Mods laden nach `rimworldmp.foundation` und registrieren in `[StaticConstructorOnStartup]` oder ihrem `Mod`-Konstruktor.
  - **Befehlstabelle statt if-Kette:** `GameCommandCodec` führt `Opcode → Ausführer`; Draft (1), Forbid (2), Goto (3) stehen in derselben Tabelle wie `SyncMethod` (4). Unbekannter Opcode bleibt `ProtocolException` (die Mod-Prüfung der Lobby schließt ungleiche Mods aus). `Run` setzt `Executing` und merkt sich den laufenden Befehl (`Current`, für `ExecutingIssuer`).
  - **Sync-Methoden (`SyncMethods`):** Kennung = FNV-1a-64 der Signatur (`Typ::Name(Parametertypen)`); Kollision wirft. Registrierung setzt einen Harmony-Prefix (Instanz `rimworldmp.foundation.api`, Priorität First) auf die Methode. Prefix: in einer gemeinsamen Partie in Phase Playing, außerhalb eines Befehls und außerhalb eines gemeinsamen Ticks (`SessionTickDriver.InTick`) wird der Aufruf kodiert, an den Koordinator gesendet und das Original übersprungen; sonst läuft das Original. Ausführung an der Tickgrenze: Empfänger und Argumente lesen, `MethodInfo.Invoke`. Fehlende Referenz (`MissingReferenceException`) → No-op mit Logzeile auf allen Clients; Ausnahme aus der Mod-Methode → `Log.Error`, Spiel läuft weiter (alle Clients sahen dieselbe). Rückgabewerte werden nicht transportiert; `ref`/`out`, generische und abstrakte Methoden sowie Struktur-Instanzmethoden werden abgelehnt. Befehlsgröße ≤ `LockstepPayloads.MaximumCommandBytes` (32 KiB), sonst wird nicht gesendet und das Original übersprungen (Statuszeile).
  - **Serialisierer (`SyncSerializer`, Plan §7.3):** Primitive, `string` (≤ 65 535 Byte), Enums (als Int64; undefinierte Werte abgelehnt), `Nullable<T>`, `T[]`/`List<T>` (≤ 65 535 Einträge), `IntVec3`, `IntVec2`, `Rot4`, `CellRect`, `LocalTargetInfo`, `Def`-Ableitungen (defName, bei abweichendem Laufzeittyp zusätzlich Typname), `Thing`/`Pawn` (platziert: Karte + ID; Weltfigur: ID; in platziertem Behälter: Karte + Träger + ID), `ThingComp` (Träger + Index), `Map` (uniqueID), `Faction` (loadID), `Zone`/`Area` (Karte + ID), `Bill` (Werkbank + `GetUniqueLoadID`). Referenztypen tragen ein Null-Bit. Eigene Typen über `SyncWorkerDelegate<T>`; Worker gelten auch für Ableitungen. Methoden werden erst nach Prüfung aller Parametertypen angenommen (Worker zuerst registrieren; `RegisterAll` hält die Reihenfolge ein).
  - **Hash-Beitrag (`SyncHashes`):** `SessionStateHash.Compute` fügt vor den Zufallszählern Anzahl, Kennung (FNV) und Wert jedes Beitrags in Kennungsreihenfolge ein; wirft ein Beitrag, zählt 0 und eine Fehlermeldung einmal.
  - **Determinismus:** Capture nur auf dem auslösenden Client, Ausführung durch denselben Code überall einschließlich Aussteller (Plan §7.2). Registrierungen müssen auf allen Clients gleich sein; das stellt die Mod-Prüfung sicher (gleiche Mods, Versionen, Reihenfolge).
  - **Versionierung:** Additive Änderungen heben die Minor-Version, Entfernungen die Major-Version; entfernte Mitglieder bleiben eine Minor-Version als `[Obsolete]` erhalten. Festgehalten in `docs/extension-api.md`.
- **Nicht enthalten:** `SyncField`/`Watch` und `SyncDelegate` (Plan §7.2; Umgehung: eine Methode als Aktion), allgemeine Erfassung beliebiger Aufträge (SYNC-004), der rwmt-`Multiplayer.API`-Vertrag (API-002), Adapterordner/Matrix/Lobby-Warnung (COMPAT-001), TOOL-002-Detektor, Berechtigungsprüfung je Mod-Befehl (ADR 0026 liefert `ExecutingIssuer`, die Prüfung liegt bei der Mod), Verben, Quests, Lords, `GlobalTargetInfo`.
- **Prüfung:** Mod-Build 0 Warnungen; Paket hat jetzt acht DLLs (`scripts/build-mod.sh`, `scripts/package-mod.py`). Selbsttest `-mpWorldSelfTest` mit neuem `ApiSelfTest`: Registrierung über `MP.RegisterAll`, lokaler Aufruf läuft durch, Kodieren/Ausführen mit 15 Argumenttypen (Pawn, ThingDef, IntVec3, string, int, float, bool, List<int>, Faction, Map, Area, eigener Worker-Typ, LocalTargetInfo, Rot4, `Def` mit Laufzeittyp), `IsExecutingCommand`/`ExecutingIssuer`, No-op bei fehlender Referenz, Ablehnung unbekannter Kennung, 32-KiB-Grenze, Hash-Änderung. Ergebnis in `docs/verification/2026-10-17-public-sync-api.md`. Kein Zwei-Client-Test, kein echter Fremd-Mod.
- **Rollback:** Projektverweis und `MP.Install` entfernen, `GameCommandCodec` behält die Tabelle ohne Opcode 4, `SyncHashes.Contribute` entfernen (ändert den Hash nicht, solange niemand registriert).
