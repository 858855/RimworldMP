# ADR 0023 – Gemeinsamer Spielstart und pausierte Landung (SETUP-005)

- **Status:** angenommen für `feat/mod-check-setup-ui`. Designnotiz nach `AGENTS.md` Regel 4. Schließt die Einrichtung aus ADR 0015/0017 ab (Phase `Generating`) und ergänzt die Phase `Playing`. Grundlage: Chunk-Kanal (ADR 0014), Figurenbesitz (ADR 0022).
- **Ziel:** Alle Spieler laden denselben Startspielstand mit gleichem Ort, gleichen Figuren und Besitzern und warten pausiert, bis der Gleichlauf (SYNC-001) existiert.
- **Start beim Host:** Der letzte vanilla-Start auf der Figurenseite geht nur weiter, wenn alle fertig sind. Vanilla prüft dann wie immer (eigene Rückfragen inklusive) und ruft am Ende `PageUtility.InitGameStart` auf. Ein Harmony-Prefix fragt dort zuerst den Server nach `Generating` und lässt den Start erst laufen, wenn der Server zugestimmt hat (zweiter Aufruf durch die Mod). Lehnt der Server ab, öffnet sich die Figurenseite wieder. Der Besitz wird beim Phasenwechsel aus `CharacterHost` übernommen.
- **Spielstand:** Nach der Kartenerzeugung füllt der Host die Spielkomponente `MultiplayerSession` (Lobby-ID, Spieler mit `PlayerKey` und Namen, Besitzer der gelandeten Startfiguren) und speichert einen normalen vanilla-Spielstand (`GameDataSaveLoader.SaveGame`, Name „Multiplayer - Lobby - Datum Uhrzeit“, nie überschrieben). Er sendet ihn gzip-komprimiert als Chunk-Übertragung der Art `3` (Game) an alle.
- **Host lädt mit:** Der Host lädt dieselbe Datei sofort selbst neu. So spielen alle denselben geladenen Zustand; der laufende Spiel-Zustand kann mehr enthalten als die Datei, und für den Gleichlauf zählt nur, was überall gleich ist. Verworfen: Host spielt das erzeugte Spiel weiter (spart ~2,5 s, aber Host und Gäste starten von verschiedenen Zuständen).
- **Gäste:** schreiben den empfangenen Spielstand in ihren Spielstandordner und laden ihn wie „Spiel laden“ (`GameDataSaveLoader.LoadGame`). Die Welt aus SETUP-002 wird vorher verworfen.
- **Fingerabdruck (32 Byte):** SHA-256 über SHA-256 der Spielstanddatei, Spieltick, Karten (ID, Feld, Größe), gelandete Kolonisten (Thing-ID, voller Name), Sitzung, Spieler und Besitzer. Host und Gäste bilden ihn erst nach dem Laden. Im `Player.log` ohne Spielerkennungen.
- **Protokoll (Wire-Version 3):** `GameReady` (35, nur Host, nur in `Generating`), `GameLoaded` (36, nur Gäste, nur in `Generating`). Der Spielerstatus im Lobbyzustand (`WorldStatus`) meldet ab `Generating` den Spielstand. Gäste dürfen vor dem Host melden (beide laden gleichzeitig); ihre Meldung zählt, sobald der Host meldet. `SetupAdvance(Playing)` verlangt die Host-Meldung und „passt“ bei allen (Abweichung Code 8, fehlende Meldung Code 6). Nach `Playing` gibt es keinen weiteren Schritt; Abbrechen und Weggang des Hosts setzen auf die Lobby zurück.
- **Pausiert:** Solange die Lobby in `Generating` oder `Playing` ist und das Spiel läuft, bleibt die Zeit stehen. Harmony auf `TickManager`: Prefix auf `TickManagerUpdate` setzt vor jedem Frame auf Pause; Prefixe auf den Geschwindigkeits-Setter und `TogglePaused` lehnen mit Hinweis ab; Prefix auf `DoSingleTick` lässt keinen Tick laufen. Das letzte ist nötig: im Selbsttest lief das Spiel trotz Rücksetzen in 50 von 239 Frames wieder an. Einzelspieler bleibt unberührt.
- **Hauptmenü-Befund:** Ohne offenes Fenster verwirft RimWorld im Hauptmenü das aktuelle Spiel (Selbsttest). Ein Gast braucht die empfangene Welt bis zur Startortwahl, deshalb lässt sich sein Multiplayer-Fenster in `WorldTransfer` und `SiteSelection` nicht schließen.
- **Anzeige:** Im Spiel ein Feld oben rechts (Phase, Fortschritt, je Spieler Figur und Ladestatus, „Pausiert bis zum Gleichlauf (SYNC-001)“, **Chat / Lobby**, **Sitzung beenden** bzw. **Sitzung verlassen**). Nach dem Ende der Sitzung läuft das Spiel als Einzelspieler-Kopie weiter.
- **Persistenz:** `MultiplayerSession` ist Teil des Spielstands; OWN-001 (Besitzanzeige) und späteres Fortsetzen bauen darauf auf. Ohne die Mod geladen, fehlt nur diese Komponente.
- **Tests:** Lobby-, Hosting- und Protokolltests für die Regeln. Selbsttest im Spiel: frisches Host-Spiel mit `InitGameStart`, speichern, als Host neu laden, als Gast laden, Fingerabdruck gleich, Pause hält (keine Ticks in 2 s), 0 Fehler. Zwei-Spieler-Lauf: **offen**.
- **Rollback:** Commits zurücknehmen; der letzte Start ist dann wieder gesperrt (Stand SETUP-004).
